# 校园公益众筹存证溯源系统 · cangku04

面向校园内部的公益项目管理与资金溯源测试系统。提供学生、社团、学校管理员、监管审计四类工作台，完整源码可下载、修改和运行。

**本版本仅用于内部测试。校园认证不是学校正式实名认证，支付和退款不转移真实资金。默认存证来源为 MOCK（业务库内持久化的模拟账本），不是已经部署的 Fabric 联盟链。仅存证摘要，原始文件保存在服务器文件卷。禁止将演示系统用于对外公开募捐。**

## 下载后启动

前提：安装并启动 [Docker Desktop](https://www.docker.com/products/docker-desktop/)（Windows/macOS），或 Docker Engine + Compose v2.20+（Linux）。Windows 使用 Linux 容器，建议 4 核、8GB 内存、10GB 可用磁盘；首次构建需要联网下载开源镜像、Maven 与 npm 依赖。

1. GitHub 页面点击 **Code → Download ZIP**，解压到普通目录（不要直接在压缩包中启动）。也可使用 `git clone` 下载源码。
2. Windows 双击根目录 **start-system.bat**；Linux/macOS 运行 `bash start-system.sh`。
3. 等待数据库、后端和前端全部健康后，打开 **http://localhost:9528/#/login**。
4. 同一局域网内的其他设备访问 `http://运行电脑的局域网IP:9528/#/login`。Windows 启动脚本会打印常见网卡地址；防火墙需允许私有网络 TCP 9528，WiFi 需允许设备互访。
5. 停止时使用 **stop-system.bat** 或 `bash stop-system.sh`。停止不会删除数据库、上传文件或备份。

脚本首次创建本地 `.env`，自动随机生成数据库密码和 JWT 密钥。源码中不包含个人数据库、用户资料、真实上传文件或本机密钥。

若 9528 已占用，在首次生成的 `.env` 中将 `WEB_PORT` 改成其他端口再启动，例如 `9530`；局域网访问时还需设置 `CAMPUS_ALLOWED_ORIGINS=http://localhost:9530,http://127.0.0.1:9530,http://10.*:9530,http://172.*:9530,http://192.168.*:9530`。不要在已有数据卷时单独修改数据库密码；应配合数据库账号改密，并备份 `.env`。

## 演示账号

所有演示账号初始密码为 **123456**，仅用于空库初始化；首次使用后可在个人信息中改密。

| 身份 | 账号 | 可操作范围 |
|---|---|---|
| 学生 | `20210001` | 测试校园认证、项目浏览、测试订单、个人捐赠、退款、溯源 |
| 社团 | `club001` | 项目申请、进度、证明材料、捐赠数据、资金提取与使用凭证 |
| 学校管理员 | `admin` | 用户、社团和项目审核，财务确认，退款审核及完成登记，公示、投诉、运维 |
| 监管审计 | `auditor` | 全部项目、资金链、存证验真、审计报告和规则，不具有财务写权限 |

首次初始化只有虚构演示账号和一个零筹款测试项目，没有伪造捐赠、占位文件或虚构链上凭证。演示项目默认有效期为初始化起 30 天。社团预置资质及测试项目的上架仅供演示，不代表真实学校审核。新社团和新项目仍走管理员审核。

## 从注册到支付、退款

1. 登录页注册学生，登录后进入“校园身份认证”，填写学号、姓名、学院并勾选测试声明。无需上传身份证明或等待学校人工审核。
2. 进入“公益项目”，选择测试项目、填写金额并创建模拟订单，在“我的模拟订单”选择模拟成功或失败。失败可以重试。成功后系统自动生成标有内部测试的回执，学生无需上传支付凭证。
3. 用 `admin` 登录学校财务工作台，核对订单、金额与自动生成的测试回执。通过才形成有效捐赠、增加净筹款并提交存证任务；驳回需填写理由，学生可重新提交，生成新的测试回执。
4. 学生在“我的捐赠记录”的操作栏点击“申请退款”，填写全额退款原因。在“退款申请记录”查看进展。旧记录若缺少财务确认关联不会被伪造为可退款记录。
5. 管理员审核退款：驳回需说明理由，学生可重新申请；通过后进入待退款，此时不扣减筹款。
6. 管理员上传**测试退款完成凭证**，登记经办人及完成时间，系统仅扣减一次净筹款并追加退款存证。此处的退款完成凭证与已取消的学生支付文件上传是不同环节。
7. 各工作台同步显示订单、有效捐赠、退款与存证状态。存证为待处理或失败时不会显示已完成，管理员可重试失败任务。

恢复正式人工身份审核：在 `.env` 中设置 `CAMPUS_IDENTITY_TEST_MODE=false` 并重新运行启动脚本。测试认证不能被当作正式认证。历史认证资料不会被删除。

## 组成与完整源码

| 目录 | 内容 |
|---|---|
| `backend/` | Spring Boot 2.7、Spring Security/JWT、BCrypt、MySQL、Fabric Gateway、财务状态机、定时备份、审计与测试 |
| `frontend/` | Vue 3、Element Plus（Vue 3 对应的 Element 组件库）、四类工作台、校园风界面 |
| `chaincode/` | Go Fabric 链码、只存摘要、事件幂等、查询和验真、单元测试 |
| `fabric-network/` | 可选真实 Fabric 2.4 多组织测试网络配置与部署脚本 |
| `database/` | 基础 ER 表、视图、独立虚构初始化数据；财务增量迁移位于 backend resources/db |
| `deploy/` | 容器部署配套配置 |
| `scripts/` | 浏览器验证、独立凭证验真和发布检查工具 |
| `docs/` | 完整接口索引、财务状态机、使用和发布验证说明 |

运行后接口文档：**http://localhost:9528/doc.html**，OpenAPI：`http://localhost:9528/v3/api-docs`。业务接口采用 `/api`，除登录注册等认证接口外需要 Bearer JWT，业务响应需要同时判断 JSON `code`。

## 存储、备份与 Fabric

MySQL 和后端只在 Docker 内部网络可访问，浏览器统一通过前端 9528 访问。数据库、原始文件、备份使用三个独立持久卷。MySQL 的基础初始化脚本**只在空数据卷执行**，后续财务迁移由后端非破坏性执行；不要把 `schema.sql` 导入已有业务库（其中包含重建基础表操作）。

后台支持手动备份和每天 02:00 定时备份。备份包含 SQL 与原始文件，保留期 30 天。迁移到其他电脑时同时保存数据库备份、上传文件和 `.env`；不要使用 `docker compose down -v`，该命令会删除数据卷。

默认 MOCK 存证用于功能测试，数据库被完全删除后不能提供独立账本核验保障。真正需要多方共识和业务库损坏后的独立核验时，应按 [Fabric 手册](fabric-network/test-network-setup.md) 部署真实联盟链，挂载自己生成的身份与 TLS 证书，并覆盖后端 Fabric 连接配置；不能只修改一个开关。仓库不包含私钥、组织身份或已运行的真实 Fabric 网络。

## 排错与验证

```bash
docker compose ps
docker compose logs --tail 100
docker compose logs -f backend
```

首次启动较久多为镜像或依赖下载；失败信息会保留在控制台。若提示端口冲突，先停用占用服务或改 WEB_PORT。若另一设备无法访问，检查 IP、私有网络防火墙和无线 AP 隔离。

实际验证范围和环境限制见 [发布验证记录](docs/发布验证记录.md)；开发与原生运行方式见 [开发说明](docs/开发说明.md)。GitHub 提供源码下载，系统网页需在下载者自己的电脑或内网服务器启动。
